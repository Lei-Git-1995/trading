# FreqUI 中文交易面板设计方案

## 1. 项目目标

为当前 Freqtrade/FreqUI 建立一套独立的中文 Web 操作界面，沿用现有 Freqtrade API、交易状态和策略能力。新界面重新整理信息层级与常用操作，桌面端优先，同时适配平板和手机。

目标用户是需要日常查看机器人状态、持仓、订单、盈亏和策略运行情况的个人交易者。页面要让用户快速回答：机器人是否正常、目前持有什么仓位、盈亏如何、最近发生了什么、接下来可以执行什么操作。

**产品文案基调：**清楚、克制、可核对。使用常见中文交易术语；收益和风险指标同时显示金额与百分比；对可能改变机器人或订单状态的操作提供明确对象、结果和二次确认。

## 2. 设计原则

1. **先看状态，再做操作。**总览优先展示机器人运行、账户余额、当前仓位和当日盈亏。
2. **高频内容少跳转。**从持仓行直接打开详情、查看图表、平仓；从交易记录进入对应成交详情。
3. **把策略参数和实际仓位分开。**运行配置、策略信息、账户余额、机器人控制各有独立区域，避免误把配置值当成交易所账户实时状态。
4. **每项数字可追溯。**提供更新时间、时间范围、数据来源和空状态说明；加载失败时说明原因并允许重试。
5. **界面默认中文，术语保留必要英文。**币对、API 字段和交易所原始状态可保留英文，并在可见处给出中文解释。
6. **危险操作显式确认。**停止机器人、强制开仓/平仓、删除回测记录等操作展示确认弹窗和影响对象。

## 3. 信息架构

```text
登录
└── 交易工作台
    ├── 总览
    ├── 当前持仓
    │   └── 持仓详情 / K 线图
    ├── 交易记录
    ├── 币种与行情
    │   ├── 币种列表
    │   ├── 币种详情 / K 线图
    │   └── 交易对管理（白名单 / 黑名单 / Pairlist）
    ├── 策略研究
    │   ├── 回测
    │   ├── 回测结果与历史
    │   ├── 前瞻偏差分析
    │   └── 递归分析
    ├── 数据管理
    │   └── 下载历史数据
    ├── 运行日志
    └── 设置
        ├── 机器人与策略
        ├── 交易所与交易模式
        ├── 风险参数与交易对配置
        └── 界面偏好
```

左侧导航在桌面端常驻，可折叠；手机端使用抽屉菜单。顶部栏固定显示机器人名称、交易所、现货/合约模式、运行状态、最近更新时间和用户菜单。页面内容区域按任务组织，不按 API 接口组织。

## 4. 页面设计文案与功能

### 4.1 登录

- 标题：**登录交易工作台**
- 字段：用户名、密码
- 主按钮：**登录**
- 辅助信息：**连接到本机 Freqtrade 服务**、连接地址、连接状态
- 错误提示：**用户名或密码不正确，请重试。** / **无法连接机器人服务，请检查服务是否正在运行。**

凭据通过现有 Freqtrade 登录 API 验证；前端不保存明文密码，不把 API 密钥写入浏览器存储或前端构建文件。

### 4.2 总览

**页标题：**交易总览  
**说明：**查看机器人运行、账户资金和近期交易表现。

页面顺序：

1. **机器人状态卡**：运行中 / 已暂停 / 已停止；策略名称；交易模式；运行时长；最后更新时间。提供“暂停开仓”“停止机器人”“启动机器人”等符合当前状态的操作。
2. **资金卡片**：总余额、可用余额、已占用金额、计价币种。数据来自余额接口，注明“交易所账户余额”。
3. **收益卡片**：今日、近 7 天、近 30 天、累计收益；每项展示净收益、收益率和已平仓笔数。时间区间可切换。
4. **当前持仓**：币对、方向、杠杆、开仓价、当前价、未实现盈亏、持仓时长；最多展示 5 条，按钮“查看全部持仓”。
5. **最近交易**：最近平仓记录、收益和退出原因；按钮“查看全部记录”。
6. **运行提示**：机器人状态变更、交易错误、交易所连接异常、数据更新时间过久等事件。

关键文案：

- 空仓：**当前没有持仓**
- 无交易：**所选时间范围内没有已完成交易**
- 刷新：**刷新数据** / **数据已更新于 10:35:20**
- 连接异常：**暂时无法获取机器人数据。** 次按钮：**重试**

### 4.3 当前持仓

**页标题：**当前持仓  
**说明：**查看未平仓交易及其风险和收益。

表格字段：交易对、方向、杠杆、开仓时间、持仓时长、开仓均价、当前价格、数量/保证金、未实现盈亏、盈亏率、止损价、策略/标签、操作。

支持按币对、方向、盈亏排序和筛选；行点击打开详情侧栏。详情侧栏展示入场订单、退出订单（如有）、止损/止盈、交易备注、自定义数据、K 线图和日志关联信息。

行操作：**查看详情**、**查看图表**、**平仓**、**取消未成交订单**、**重新载入交易状态**。平仓弹窗明确展示币对、方向、数量和预计影响，支持市价/指定退出方式（以服务端支持能力为准）。

### 4.4 交易记录

**页标题：**交易记录  
**说明：**查询已完成和进行中的交易。

默认展示最近交易，可按日期范围、币对、方向、盈亏状态、策略标签筛选；支持分页和导出当前筛选结果（导出作为新页面补充能力）。列表字段：开仓/平仓时间、币对、方向、成交均价、净盈亏、盈亏率、手续费、退出原因、持续时间。

点击记录查看完整成交详情、订单列表、策略备注、自定义数据和关联图表。保留 FreqUI 当前查看历史、交易详情、交易标签和收益分布的能力。

### 4.5 币种与行情

**币种列表**展示白名单/动态 Pairlist 当前交易对、最新价格、24 小时变化（若接口提供）、策略信号摘要、当前是否持仓。支持搜索币对和切换周期。

**币种详情**展示 K 线图、时间周期选择、策略指标/入场出场标记、当前持仓和该币种历史交易。图表时间范围支持缩放、拖动和重置。

**交易对管理**保留白名单、黑名单、Pairlist 状态和 Pairlist 配置查看/管理功能。新增或移除币种前显示影响说明；配置项按策略与 Pairlist 类型分组呈现，不直接暴露难以理解的原始 JSON，另提供高级 JSON 查看入口。

### 4.6 策略研究

#### 回测

以表单配置策略、币对、时间周期、日期范围、初始资金和必要的策略参数，提交前显示参数摘要。执行期间显示排队/运行/完成/失败状态、进度和取消操作。

#### 回测结果与历史

保留现有回测配置、回测执行、回测历史列表、结果详情、收益曲线、交易分布、指标统计和删除历史结果的能力。结果重点显示净收益、收益率、最大回撤、总交易数、胜率、Profit Factor、平均持仓时长和基准市场变化。指标旁提供简短解释。

#### 前瞻偏差分析 / 递归分析

分别提供参数说明、选择策略与币对、启动分析、任务状态、结果明细和失败提示。技术分析字段保留原始名称并配中文说明，避免错误翻译导致对策略诊断的误解。

### 4.7 数据管理

**页标题：**历史数据下载  
**说明：**下载回测和分析所需的行情数据。

表单字段：交易所、币对、时间周期、数据类型、起止时间/天数、是否覆盖已有数据。提交后显示任务进度和结果摘要；提供数据集列表与下载历史（如后端支持）。危险的覆盖操作须二次确认。

### 4.8 运行日志

保留实时/最近日志查看能力，支持级别筛选、关键词搜索、自动滚动开关、暂停刷新、复制当前日志和限制条数。日志原文保持不翻译，页面控件与级别说明中文化；错误行提供时间与上下文，避免隐藏诊断信息。

### 4.9 设置

#### 机器人与策略

展示机器人名称、当前策略、运行状态、策略版本、策略参数摘要、最大并发交易数、基础时间周期。

#### 交易所与交易模式

展示交易所、现货/合约、保证金模式、计价币种、杠杆设置和 API 连接状态。敏感密钥只显示掩码；默认只读，修改项经 API 能力确认后开放。

#### 风险参数与交易对配置

展示单笔资金、余额使用比例、最大持仓、未成交订单超时、止损/清算缓冲、白名单和黑名单。修改前展示变更前后值和“重新加载配置”的影响。

#### 界面偏好

语言（简体中文）、主题（浅色/深色/跟随系统）、数字精度、时区、收益计算显示方式、默认时间范围、自动刷新间隔。

## 5. 视觉与交互规范

- **布局：**桌面采用 240px 左侧导航 + 顶部状态栏 + 主内容区；主内容最大宽度约 1440px。手机端改为顶部状态摘要和抽屉导航，表格转换为信息卡片。
- **风格：**深色交易工作台作为默认主题，提供浅色主题；背景使用低对比深灰，卡片分层清楚，强调色用于导航和主操作，避免大面积荧光色。
- **盈亏颜色：**盈利/亏损颜色在偏好设置中可切换为红涨绿跌或绿涨红跌；同时显示正负号和文字/图标，不只依赖颜色表达。
- **排版：**中文界面使用清晰的无衬线字体；价格、数量、收益使用等宽数字；小数位按币种精度显示，尾数可展开查看。
- **数据更新时间：**关键数据旁显示时间；自动刷新默认 5 秒，允许暂停；避免刷新时整个页面闪烁。
- **反馈状态：**每个模块独立显示加载、空数据、错误和重试状态；操作成功/失败使用明确的中文提示。
- **确认层级：**普通筛选立即生效；机器人控制、强制开仓/平仓、批量变更、删除记录使用确认弹窗；提交按钮显示正在处理状态并防止重复点击。

## 6. 功能迁移清单

本地 FreqUI 资源识别到的现有主要模块及迁移对应关系：

| 当前模块/能力 | 新页面归属 | 迁移说明 |
|---|---|---|
| 登录 | 登录 | 沿用 API 登录认证 |
| Dashboard | 总览 | 重排为状态、资金、收益、持仓、近期事件 |
| Open Trades / Trade Detail | 当前持仓 / 持仓详情 | 保留详情、订单、退出、取消订单、重载等能力 |
| Trade History / Trade Profit | 交易记录 / 收益 | 保留筛选、详情、收益统计与分布 |
| Pair Summary / Candle Chart | 币种与行情 | 保留币种概况、K 线、时间周期和图表交互 |
| Pairlist / Pairlist Config | 交易对管理 | 保留白名单、黑名单、动态 Pairlist 与配置操作 |
| Backtest / Backtest History | 策略研究 / 回测 | 保留执行、任务状态、历史结果、图表和指标 |
| Lookahead Analysis | 前瞻偏差分析 | 保留运行、进度及分析结果 |
| Recursive Analysis | 递归分析 | 保留运行、进度及分析结果 |
| Download Data | 数据管理 | 保留下载参数和任务结果 |
| Logs | 运行日志 | 保留实时日志、刷新和筛选能力 |
| Settings | 设置 | 保留机器人、策略、交易所、风险及界面设置；仅开放 API 支持的写操作 |
| Bot Control | 顶部状态栏 / 总览 | 按运行状态提供启动、暂停、停止与恢复操作 |
| Balance / Performance / Profit / Stats | 总览 / 收益 | 以中文指标卡和图表呈现 |
| Whitelist / Blacklist / Locks | 交易对管理 / 风控 | 提供查看、增删和锁定管理 |

不把原页面中的某项功能默默省略。若某个控件依赖当前 Freqtrade API 不支持的写入能力，新页面标出只读状态，并在迁移验收表中记录原因。

## 7. API 与技术实现建议

- 新建独立前端目录（建议 `web/`），使用 Vue 3 + TypeScript（与当前 FreqUI 技术栈相近）或 React；页面资源独立构建、独立启动，不修改 `.venv` 内的 FreqUI 静态文件。
- 浏览器通过同源反向代理或开发服务器代理访问 Freqtrade API，避免把跨域和 API 凭据散落在页面中。开发环境代理指向本机 API 地址；部署时继续限制在本机或可信内网。
- 认证复用 `/api/v1/token/login` 与现有 JWT 机制；HTTP API 使用现有 `/api/v1` 路由，WebSocket 订阅运行状态/日志（以服务端版本支持为准）。
- 主要 API 范围包括：机器人状态与控制、余额/收益/统计、持仓和历史交易、交易详情和强制交易、白名单/黑名单/锁定、K 线/市场数据、日志、配置/策略、回测、数据下载、Pairlist、前瞻偏差和递归分析。
- 由 API 能力映射页面功能，复用 Freqtrade 作为唯一交易状态来源。前端不直连交易所，不另存订单数据库，不自行推算后端没有提供的已实现收益。
- 配置修改和高风险交易操作分开实现；初始迭代先完成只读信息和既有控制操作，再逐项开放写操作并核对 API 约束。

## 8. 交付阶段

### 阶段一：工作台基础与常用监控

登录、导航、机器人状态、总览、余额与收益、当前持仓、持仓详情、交易记录、日志、中文错误和空状态。

### 阶段二：行情和交易管理

K 线与币种详情、Pairlist、白名单/黑名单、锁定管理、启动/暂停/停止、平仓和强制操作确认流程。

### 阶段三：策略与维护工具

回测、回测历史与结果、前瞻偏差分析、递归分析、历史数据下载、完整设置和移动端打磨。

每阶段交付可运行版本，并用真实 API 响应核对字段、权限、错误和状态变化。迁移完成后以功能清单逐项验收，确保旧界面的主要能力都有新入口。

## 9. 验收标准

1. 登录、登出、令牌过期和 API 连接失败均有明确反馈。
2. 所有列入迁移清单的功能均能从新页面找到入口；不能支持的操作有明确说明。
3. 总览、持仓、历史交易、日志和机器人状态与 Freqtrade API 返回一致，显示数据更新时间。
4. 启停机器人、强制交易、平仓、配置修改和删除等操作均能确认目标、反馈结果，并正确处理失败。
5. 页面无英文主导航和未翻译的常用操作文案；策略日志、策略名和交易所原始错误信息保留原文。
6. 桌面宽屏、常见笔记本、平板和手机均可完成查看持仓与交易记录的主要任务。
7. API 凭据不写入浏览器持久化存储、公开静态文件或仓库示例配置。

## 10. 当前假设与需确认项

- 本方案以当前项目内 FreqUI 模块和本机安装的 Freqtrade API 能力为迁移基线；最终实现前按实际运行的服务版本核对接口差异。
- 默认提供中文、深色优先，并允许切换浅色主题及盈亏颜色方案。
- 回测和分析可能耗时较长，按后台任务处理，支持查看进度和结果。
- 交易相关按钮按现有机器人权限启用；页面确认只用于避免误触，不改变策略或交易逻辑。
